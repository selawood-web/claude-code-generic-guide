# Project memory

## Learned

- Probe runs test committed HEAD: `tools/audit_probes.py` unpacks `git archive HEAD`, so a run started before the commit does not cover the change. Commit first, then run probes. A probe can also pass only because of a bug, so re-read any probe whose mutation a fix touches. — tags: #tooling #testing
- Decided: the charter's portable core moves to `.claude/references/charter-core.md`, imported from `WORKING-CHARTER.md`, over `.claude/rules/` auto-loading and marker rewrites. Reason: `update.sh` already syncs `references/` and never rewrites rule files, so no project edit is overwritten and no rule loads twice. Record: `decisions/2026-11-26-sync-charter-core-separately-from-project-constraints.md`. — tags: #architecture #decision
- Check a test command's own exit code before committing: `cmd | tail -3 && git commit` commits on `tail`'s success even when the tests fail. Write the output to a file, then test `$?`. — tags: #tooling #testing
- A scripted walk's failing check is confirmed against its screenshot before it is reported: the first GBB walker called a Projects link outside the nav landmark and a Back button "dead ends". — tags: #gbb #testing
- A product fact written into a rule or doc is read verbatim from the current docs first. Fetched pages are often read only in part, with the rest summarized by a model; a claim that rests on that summary is not a fact. Ask the fetch for verbatim quotes and an UNVERIFIED mark on everything else. The charter's "every edit invalidates the prompt cache for all following sessions" was such a claim (cache lifetime is 5 minutes by default; a change ends the hit from that byte on). — tags: #docs #currency
- Subagent worktrees branch from the default branch unless `worktree.baseRef` is `"head"`. `.claude/settings.json` sets `head` so the audit verifier checks the commit under audit; removing it silently verifies findings against `master`. Files git ignores do not exist in the worktree, which is why the verifier gets its batch inline. — tags: #audit #harness
- A test that rebuilds a hook's state path must ask the same bash for it (`bash -c 'printf %s "${UID:-user}"'`): Windows Python has no `os.getuid`, while Git Bash sets `$UID` to a number. A test synced into installed projects must not assert a setting only the project's owner sets; guard it with the `install.sh` marker. Both broke the memome-1 install. — tags: #testing #windows
