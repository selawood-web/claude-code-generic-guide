## Decisions & rationale
- Unpinned syncs only from the default branch: a clone left on a feature branch would
  ship unmerged guide code; the session-start hook always pins, so only manual runs change.
- A project's permissions stay its owner's: `update.sh` keeps writing only hook
  registrations, and the guide test that asserted a project permission now skips outside
  the guide (4A over 4B, which would have widened what updates may change).
- Personal skills shadow project skills of the same name on that machine, so CCGG skills
  live in projects, not in `~/.claude/skills` (2A).
- A vetted skill's text does not vet a program it downloads at run time (3A).

## Worth remembering
- On Windows, Python has no `os.getuid` but Git Bash sets `$UID`; a test that rebuilds a
  hook's path must ask the same bash, not guess.
- A test synced into installed projects must not assert a setting only the project's
  owner may set; guard it with the `install.sh` marker.
