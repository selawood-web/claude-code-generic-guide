## Decisions & rationale
- Memory in the repo, not a memory branch or auto memory: only the repo survives a cloud
  container, and it reaches master through the same PR as the work.
  Record: `decisions/2026-11-03-repo-tracked-memory.md`.
- One log file per flush, named by UTC stamp to the second: two branches never conflict.
- Flush guard is its own hook file so `update.sh` registers it in installed projects; its
  `context_tokens` copy is held byte-identical to context-guard's by a test.
- `/flush` commits but never pushes: the validator forbids a push from a skill the model can
  start on its own.
- Dropped the "decision revisit due" count: no machine-readable trigger, would be noise.
